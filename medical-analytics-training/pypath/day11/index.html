🤔 Why this matters

Yesterday you learned to load a table and look at it. But looking is not enough: real questions sound like "Which orders were bigger than 8 items?" or "Which shop made the most money?". To answer them you filter (keep some rows), sort (put rows in order) and group (add up per shop, per product, per month).

Think of a big pile of receipts. Filtering is picking out only the coffee receipts. Sorting is putting them from biggest to smallest. Grouping is making one small pile per shop and writing the total on each pile. Almost every data analysis, and every report your boss will ever ask for, is made of these three moves.

Remember: the code boxes on this page share their variables, like pages of one notebook. Run them from top to bottom. If you see a NameError, you probably skipped a box above. The first box loads pandas, which can take a few seconds.

🔍 Filtering: keeping only some rows

Filtering happens in two steps. First, a comparison on a column gives one True or False per row, just like comparing a NumPy array on Day 9. This list of True/False values is called a mask (or a boolean filter):

Second, you put the mask inside square brackets after the table. pandas keeps the rows where the mask is True and drops the others. Read sales[sales["qty"] >= 8] as "sales, where qty is at least 8":

🧩 Two conditions at once

What about "big orders in the Mall"? That's two conditions. In normal Python you'd write and, but on a whole column that doesn't work. Watch:

Shift + Enter

"The truth value of a Series is ambiguous" means: and wants one True or False, but each side is a whole column of them, and Python doesn't know how to squeeze 30 answers into one. pandas has its own symbols that combine two masks row by row:

SymbolMeansKeeps a row when…
&andboth conditions are True
|orat least one condition is True
~notthe condition is False
Shift + Enter

Always put brackets around each condition when you use & or |: (A) & (B). Without them Python reads the line in the wrong order and you get a confusing error.

Two shortcuts save a lot of typing:

  • .isin([...]): is the value one of these? (instead of many |)
  • .between(low, high): is the number between low and high? (both ends included)

🗂️ Grouping: one answer per group

"How much money did each shop make?" is a grouping question. With groupby, pandas does three things for you:

  1. split the rows into groups (one pile per store),
  2. apply a calculation to each pile (for example, sum the revenue),
  3. combine the answers into one small result.
Shift + Enter

Read it as: "group the sales by store, take the revenue column, and sum it". The result is a Series whose labels are the store names. Swap sum for mean, count, min or max to ask other questions. .idxmax() gives the label of the biggest value (like argmax on Day 9, but it returns the name instead of a position):

⚠️ Common mistakes

  • Using and / or between columns → ValueError: The truth value of a Series is ambiguous. Use & and |.
  • Forgetting brackets around each condition: write (sales["qty"] > 5) & (sales["store"] == "Mall").
  • Writing = instead of == inside a filter. One = stores, two compare.
  • Expecting the filter to change sales. It returns a new table; store it in a variable.
  • Forgetting which column to summarise: groupby("store").sum() tries to add up every column, even the text ones. Pick one: groupby("store")["revenue"].sum().

✅ Recap

  • Filter: df[df["col"] > 5]. The comparison makes a True/False mask.
  • Combine masks with & (and), | (or), ~ (not), with brackets around each one.
  • .isin([...]) and .between(low, high) are handy shortcuts.
  • Sort: sort_values("col", ascending=False); top rows: nlargest(3, "col").
  • Group: df.groupby("a")["b"].sum(); several results: .agg(...); labels back to a column: reset_index().
  • pd.pivot_table makes a grid; pd.merge(left, right, on="key", how="left") joins two tables.
