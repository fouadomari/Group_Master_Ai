Cleaning messy data

🎯 Today's goal

By the end of this hour you will:

  • spot problems in a table: empty cells, duplicate rows, wrong types, odd values
  • remove or fill empty cells with dropna and fillna
  • tidy text (extra spaces, capital letters, different spellings) and fix column names
  • turn text into numbers with pd.to_numeric and into dates with pd.to_datetime
  • find impossible values (like an age of 250) and fix them with .loc

🤔 Why this matters

Yesterday's café data was perfectly tidy. Real data almost never is. People type "cairo", "Cairo " and "CAIRO" for the same city, forms get sent twice, someone writes "unknown" where a number should be, and a slip of the finger turns an age of 25 into 250.

Cleaning data is like washing vegetables before cooking: not exciting, but skip it and the whole meal is spoiled. Data scientists often say they spend most of their time cleaning. A chart or a machine-learning model built on messy data gives wrong answers without any warning, so this is one of the most useful skills in the whole course.

The spend column is text, because a few cells contain words. Text can't be averaged, so this fails:

"Cannot perform reduction 'mean' with string dtype" means: you can't average text. astype(float) would fail too, on the word unknown. pd.to_numeric(..., errors="coerce") converts what it can and turns everything else into NaN. (Coerce means "force": "if you can't convert it, make it empty".)

Now it works. unknown, ninety and the empty cell became NaN, and mean() simply skips NaN. But that average is still wrong. Why? Read on.

🕳️ Step 6: drop or fill the empty cells?

There are two choices for an empty cell, and both are fine in the right place:

MethodWhat it doesGood when…
dropna()removes rows with an empty cellonly a few rows are affected, or the value can't be guessed
fillna(value)writes a value into the empty cellsa typical value is a fair guess (the median, the mean, 0, "Unknown")

For ages we fill in the median (the middle value), which isn't pulled up or down by unusual ages. For spending, a guess would distort exactly the number we care about, so we drop those rows. subset=["spend"] means "only look at the spend column":

🧭 A cleaning checklist

  1. Look: shape, head(), info(), isna().sum(), duplicated().sum().
  2. Duplicates: drop_duplicates().
  3. Names: rename(columns={...}) into short snake_case.
  4. Text: .str.strip(), .str.title(), replace({...}); check with value_counts().
  5. Types: pd.to_numeric(..., errors="coerce"), pd.to_datetime(...).
  6. Impossible values: find with a filter, set to np.nan with .loc.
  7. Empty cells: fillna or dropna, and write down which.
  8. Check again: info() and isna().sum().

⚠️ Common mistakes

  • Forgetting to store the result: clean.dropna() alone changes nothing. Write clean = clean.dropna().
  • Forgetting .str: clean["city"].strip() gives an AttributeError; write clean["city"].str.strip().
  • Changing cells without .loc: clean["age"][4] = 30 does nothing in pandas 3.
  • Dropping too much: dropna() without subset removes a row if any column is empty.
  • Filling everything with 0: a missing age is not age 0. Choose a value that makes sense.

✅ Recap

  • Find problems with info(), isna().sum(), duplicated().sum() and value_counts().
  • drop_duplicates() removes copies; rename(columns={...}) fixes names.
  • .str.strip(), .str.lower(), .str.title() and replace({...}) tidy text.
  • pd.to_numeric(col, errors="coerce") makes numbers (bad values become NaN); pd.to_datetime makes dates, and .dt.month gives the month.
  • Impossible values: df.loc[condition, "col"] = np.nan.
  • Empty cells: fillna(value) or dropna(subset=[...]).
