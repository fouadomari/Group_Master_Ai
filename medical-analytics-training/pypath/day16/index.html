🤔 Why this matters

Until now, you found the patterns: on Day 15 you discovered that women and first-class passengers survived more often. Machine learning (ML) means letting the computer find patterns by itself, from examples, and then use them to make guesses about new cases it has never seen.

It's how a child learns what a dog is. Nobody gives them a rule book ("four legs, fur, barks…"). They see many dogs and many cats, someone says which is which, and after a while they can recognise a dog they've never met. Spam filters, film recommendations and medical image tools all learn this way.

Remember: the code boxes on this page share their variables, like pages of one notebook. Run them from top to bottom. The first box that uses scikit-learn needs a few extra seconds to load it.

📏 Rules versus learning

The old way is to write the rules yourself with if / else (Day 4). Here's a hand-written rule that guesses a fruit from its weight and how smooth its skin is (0 = very bumpy, 10 = very smooth):

Shift + Enter

This works for easy cases, but who decided that 6 is the right cut-off? And what about the weight? With 2 measurements you can still invent rules; with 30 measurements, nobody can. In machine learning we turn it around:

  • Rules: you write the rules → the computer applies them to data → answers.
  • Machine learning: you give data and the right answers → the computer works out the rules → it can answer new cases.

📖 The words you'll hear every day from now on

WordMeaningIn the fruit example
featurea measurement we know about each example (an input column)weight, smoothness
label (or target)the answer we want to predict"apple" or "orange"
modelthe thing that learns the pattern and then makes guessesa "fruit guesser"
fit (or train)let the model learn from examples with known labelsshow it 100 labelled fruits
predictask the model for its guess on new examples"what is this new fruit?"

By tradition the features are stored in a variable called X (capital, because it's a whole table) and the labels in y (lower case, because it's one column).

Two more pairs of words describe the kind of problem:

  • Supervised learning: every example comes with its label, like a teacher who gives the answers while you practise. That's all of this week. Unsupervised learning: no labels at all, the computer just looks for groups (Day 21).
  • Classification: the label is a category (apple / orange, survived / didn't, spam / not spam). Regression: the label is a number (a price, a temperature). Day 17 is about regression.

📚 Why we hide some data: the train/test split

Imagine a teacher gives the class the exact exam questions to practise. Everybody scores 100%, but did anybody learn anything, or did they just memorise? The only fair test uses questions the students have never seen.

Models are the same. So before training, we put part of the data aside:

  • the training set (usually 70–80%): the model learns from it
  • the test set (the other 20–30%): kept hidden, used only at the end to check how well the model does on flowers it has never seen

train_test_split shuffles the rows and cuts them into the two parts:

random_state=42 works like the NumPy seed: the shuffle is "random" but the same every time, so your results match this page. stratify=y makes sure each species is shared out fairly. Without it, by bad luck, the test set might get almost no setosas:

🤖 Your first model

Every scikit-learn model is used with the same four steps. Learn them once and you can use dozens of different models:

  1. create the model: model = SomeModel()
  2. fit it on the training data: model.fit(X_train, y_train)
  3. predict new cases: model.predict(X_test)
  4. score it on the test data: model.score(X_test, y_test)

Our first model is called k-nearest neighbours (KNN). Its idea is simple: to guess the species of a new flower, find the 5 training flowers that are most similar to it, and let them vote. You'll look inside it on Day 18.

🪜 Is 97% good? Compare with a baseline

A score means little on its own. A baseline is the score of a "lazy" model that doesn't look at the features at all, for example one that always guesses the most common species. A real model must beat it clearly, otherwise it learned nothing useful. scikit-learn has such a lazy model, called DummyClassifier:

Shift + Enter

With three equal species, always guessing the same one is right about a third of the time. Our model is far better than that. Baselines matter even more when one answer is very common: on Day 15's ship, guessing "did not survive" for everyone would already be right 59% of the time.

⚠️ Common mistakes

  • Judging a model on its training data. It may have just memorised it.
  • Mixing up the order: it's X_train, X_test, y_train, y_test = train_test_split(X, y, ...).
  • Calling predict before fit → NotFittedError.
  • Giving one example with single brackets [5.0, 3.4, 1.5, 0.2]: models want a table, [[...]].
  • Forgetting random_state=42, so your numbers change every run and don't match the page.
  • Getting excited about an accuracy without checking the baseline.

✅ Recap

  • Machine learning = learning the rules from labelled examples, instead of writing them by hand.
  • Features X are the inputs, the label y is the answer. Classification predicts categories, regression predicts numbers.
  • train_test_split(X, y, test_size=0.25, random_state=42, stratify=y) hides a test set.
  • Every model: create → fit → predict → score.
  • Accuracy = share of correct guesses = (predictions == y_test).mean().
  • Always compare with a baseline such as DummyClassifier(strategy="most_frequent").
