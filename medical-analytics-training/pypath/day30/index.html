She doesn't want to read every review, and she doesn't want to run ten code boxes. She wants one call that gives an answer.

That's what a capstone is: a final project that joins everything together. Real data work looks exactly like this. Small, tested pieces (cleaning, a model, a few counts) are combined into a tool that someone else can use with one line.

⚠️ Common mistakes

  • Misspelling a dictionary key → KeyError. Check with result.keys().
  • Dividing by len(reviews) when the list is empty → ZeroDivisionError. Check first, or raise a clear error.
  • Using double quotes for a key inside a double-quoted f-string: a SyntaxError before Python 3.12. Use result['count'], which works everywhere.
  • Fitting the model inside analyze(). Train once, outside; the function only predicts.
  • Trusting the tool more than the data it learned from.

✅ Recap

  • A capstone joins small, tested pieces into one tool: clean → vectorise → classify → summarise → report.
  • Train the final model on all the labelled data once you've tested the recipe.
  • analyze() returns a dictionary, so every result has a name.
  • report() and a chart turn numbers into something a person can act on.
  • Know the limits of your model, and say them out loud.
