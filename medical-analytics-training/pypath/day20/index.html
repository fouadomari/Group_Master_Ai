🤔 Why this matters

Imagine a smoke alarm that never rings. In a normal year there is no fire on 364 days, so the alarm is "right" 99.7% of the time. It is also completely useless: on the one day that matters, it stays silent.

Models are the same. One number (accuracy) hides which kind of mistake the model makes. Missing a sick patient is much worse than sending a healthy person for one more check. Today you'll learn the tools data scientists use to see the full picture before they trust a model.

🧩 The four kinds of answer

For a yes/no question there are exactly four possibilities. We call the class we're looking for (sick) the positive class. "Positive" doesn't mean good; it means "the thing we're searching for".

🎯 Precision, recall and F1

From the four counts we build three famous scores. Each answers a different question:

ScoreFormulaThe question it answers
PrecisionTP / (TP + FP)When the model says "sick", how often is it right? (few false alarms)
RecallTP / (TP + FN)Of all the really sick people, how many did it find? (few missed cases)
F12 × P × R / (P + R)One number that is only high when precision and recall are both high
Shift + Enter

F1 is a special kind of average (the "harmonic mean") that punishes a weak side: a model with precision 1.0 and recall 0.1 gets an F1 of only 0.18, not 0.55. scikit-learn has a function for each score. Let's also score the lazy model from the start:

Shift + Enter

The 95%-accurate lazy model has a recall and F1 of 0. Now its uselessness is visible.

Which one matters? It depends on the cost of each mistake. Missing a sick patient or a fraud is expensive → care most about recall. A spam filter that hides an important email is annoying → care most about precision. No clear winner → look at F1.

🔁 Cross-validation: more than one exam

Our test score depends on which rows happened to land in the test set (you saw this with the jumpy trees on Day 19). Cross-validation gives a fairer score. With cv=5:

  1. The data is cut into 5 equal parts, called folds.
  2. The model is trained 5 times. Each time, one fold is the test set and the other 4 are for training.
  3. You get 5 scores. Their mean is the fair estimate, and their spread (standard deviation, Day 9) shows how steady the model is.
Shift + Enter

Notice we give cross_val_score the whole X and y; it does the splitting itself. scoring="recall" (or "precision", "f1"…) chooses the score.

📐 One more score: ROC AUC (briefly)

Precision and recall depend on the threshold. ROC AUC looks at all thresholds at once and asks: if I pick one random malignant case and one random benign case, how often does the model give the malignant one the higher probability? 1.0 is perfect, 0.5 is coin-flipping. 📋 A model-evaluation checklist

  1. How balanced are the classes? Compare with the "always the common answer" baseline.
  2. Look at the confusion matrix: which mistake does the model make?
  3. Which mistake is more expensive? Choose recall, precision or F1 accordingly.
  4. Pick the threshold on purpose, not just the default 0.5.
  5. Use cross-validation for a fair, steady score, and always evaluate on data the model hasn't seen.

⚠️ Common mistakes

  • Trusting accuracy on imbalanced data. A model that always says "no" can look excellent.
  • Mixing up the order: score functions want (real answers, predictions), real first.
  • Forgetting which class is "positive". Precision and recall are about class 1 unless you say otherwise.
  • Passing lists of different lengths → ValueError: inconsistent numbers of samples.
  • Giving roc_auc_score the 0/1 predictions instead of the probabilities.
  • Judging a model from one lucky (or unlucky) test split. Use cross-validation.

✅ Recap

  • Confusion matrix: tn, fp, fn, tp = confusion_matrix(y_true, y_pred).ravel().
  • Precision = TP / (TP + FP): how trustworthy the alarms are.
  • Recall = TP / (TP + FN): how many real cases were found.
  • F1 = 2·P·R / (P + R): high only if both are high. classification_report shows them all.
  • The threshold (default 0.5) trades precision for recall: (proba >= t).astype(int).
  • cross_val_score(model, X, y, cv=5) gives 5 scores; report their mean.
