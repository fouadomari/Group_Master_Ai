Writing your own functions

🤔 Why this matters

You've already used lots of functions: print(), len(), sum(), round(). Someone wrote them once, and now everyone can use them without knowing what's inside. Today you'll write your own.

A function is like a recipe card. You write the steps once and give the card a name ("pancakes"). Whenever you want pancakes, you just say "pancakes" and maybe "for 4 people", instead of repeating every step. In data work you'll write functions like clean_price() or average() and use them on thousands of rows. And when a step needs fixing, you fix it in one place.

🧩 Your first function

You define (create) a function with the word def, a name, round brackets and a colon. The steps go in an indented block, just like with if and for. Defining a function doesn't run it yet. You run it by calling it: its name followed by brackets.

A function becomes useful when you can give it information. The names inside the brackets are called parameters: variables that get their value when the function is called. The value you pass in is called an argument.

🖨️ print is not return

This trips up almost everyone. print only shows a value on the screen, for a human to read. return hands it back to your code, so the program can keep using it. Look what happens with a function that prints instead of returning:

Shift + Enter

A function without return gives back None, Python's "nothing". If you later try result + 10, you'd get a TypeError. Rule of thumb: functions should return their answer; print it outside, when you want to see it.

🔒 What happens inside stays inside

Variables created inside a function are local: they exist only while the function runs, and they don't touch variables with the same name outside. That's a good thing: you can use a name like total in a function without worrying that it breaks the rest of your code.

Shift + Enter

Good habit: give a function everything it needs through its parameters, and get everything out through return. Then it works the same wherever you use it.

⚠️ Common mistakes

  • Defining a function but never calling it. Nothing happens until you write name(...).
  • Calling it without brackets: say_hello just names the function; say_hello() runs it.
  • Printing instead of returning, so the result is None.
  • Putting return inside a loop by accident: the function ends during the first round.
  • Forgetting an argument → TypeError: … missing 1 required positional argument.
  • Expecting a variable made inside a function to exist outside it. Return it instead.

✅ Recap

  • def name(parameters): + an indented block creates a function; name(arguments) calls it.
  • return value hands the answer back and ends the function. Without it, you get None.
  • Defaults: def f(price, tax_rate=0.2):. Named arguments: f(50, tax_rate=0).
  • return a, b returns a tuple; unpack it with x, y = f(...).
  • Variables inside a function are local. A docstring describes the function.
  • sorted(items, key=len) or key=lambda p: p["age"] sorts by your own rule.
