🤔 Why this matters

Imagine two students preparing for an exam with last year's questions. One memorises the answers word for word: perfect on last year's paper, lost when the questions change. The other learns the ideas: a little less perfect on the practice paper, but fine on the real exam. Models can be either student.

Yesterday your network scored almost 100% on its training pictures and a bit less on new ones. That difference is the most important warning sign in machine learning, and big neural networks, with their thousands or millions of weights, are especially good at memorising. Today you'll learn to see it and to fix it.

🧪 Why a validation set?

We just chose a depth by looking at scores. If we had used the test set for that, we would have picked the depth that happens to suit those 80 test points, and the test score would no longer be an honest "unseen data" score. It's like practising with the real exam paper. So: choose with the validation set, then use the test set once, at the very end.

📚 More data helps

The best cure for overfitting is more examples: it's hard to memorise 10 000 points, so the model is pushed to learn the real pattern. A learning curve shows the scores as the training set grows. learning_curve does this with cross-validation (Day 20) and gives one score per fold; we take the mean of each row:

Shift + Enter

With 20 examples the model looks great on training data and poor on new data. With more examples the two lines come close together. In deep learning, collecting more (and cleaner) data is often worth more than any clever trick.

🧲 Regularisation: keeping a network modest

When you can't get more data, you regularise: you hold the model back from becoming too complicated. For a tree that's max_depth. For a neural network there are three common tools.

1. Weight penalty: alpha

Overfitting networks tend to grow some very large weights to twist themselves around single points. alpha adds a penalty for large weights to the loss (called L2 regularisation), so the network prefers small, calm weights and smoother answers. Bigger alpha = stronger penalty. Here a big network (two hidden layers of 64) gets only 60 training points, a recipe for memorising:

Shift + Enter

With almost no penalty, the network is perfect on its 60 points and worse on new ones. With alpha=1.0 it is less perfect on training data but better on validation: exactly the trade we want. (alpha is a setting you choose by validation, like max_depth.)

2. Early stopping

During training, a network first learns the general pattern and later starts memorising. Early stopping watches a validation score while training and stops when it hasn't improved for a while. With early_stopping=True, MLPClassifier keeps 10% of the training data aside for this and stops after 10 epochs without improvement. n_iter_ tells you how many epochs it really ran:

Shift + Enter

Fewer epochs, less time, and here even a better validation score.

3. Dropout (explained, not run)

Dropout is the favourite trick in big networks. During training, every step randomly switches off a share of the neurons (for example 20%). The network can never rely on one particular neuron, so knowledge gets spread out, like a team where anyone might be absent on a given day, so everybody learns the whole job. When the network is used for predictions, all neurons are switched back on. scikit-learn's MLPClassifier doesn't have dropout, but the frameworks below do: it's a single line.

🏭 Real-world frameworks: PyTorch and Keras

Both examples below build the digits network from yesterday: 64 inputs → 64 hidden neurons → 10 outputs.

PyTorch · read-only example, not runnable here

import torch
from torch import nn

# 64 inputs → 64 hidden neurons (ReLU) → 10 outputs
model = nn.Sequential(
    nn.Linear(64, 64),      # weights + biases, like W1 and b1
    nn.ReLU(),              # the activation
    nn.Dropout(0.2),        # dropout: switch off 20% while training
    nn.Linear(64, 10),      # like W2 and b2
)
loss_fn = nn.CrossEntropyLoss()      # log-loss for classes
optimizer = torch.optim.Adam(model.parameters(), lr=0.001,
                             weight_decay=0.0001)   # like alpha

X = torch.tensor(X_train, dtype=torch.float32)
y = torch.tensor(y_train)

for epoch in range(100):             # 100 epochs
    prediction = model(X)            # forward pass
    loss = loss_fn(prediction, y)    # how wrong?
    optimizer.zero_grad()            # clear the old gradients
    loss.backward()                  # backpropagation, done for you
    optimizer.step()                 # one gradient-descent step

That's yesterday's loop: forward pass, loss, backpropagation, update. The difference is that loss.backward() works out every gradient automatically, for any network you can imagine. Keras hides the loop completely:

Keras · read-only example, not runnable here

from tensorflow import keras

model = keras.Sequential([
    keras.Input(shape=(64,)),
    keras.layers.Dense(64, activation="relu"),
    keras.layers.Dropout(0.2),
    keras.layers.Dense(10, activation="softmax"),
])
model.compile(optimizer="adam",
              loss="sparse_categorical_crossentropy",
              metrics=["accuracy"])

stop = keras.callbacks.EarlyStopping(patience=10)   # early stopping
model.fit(X_train, y_train, epochs=200,
          validation_split=0.1, callbacks=[stop])

Why GPUs? A network's work is mostly matrix products like X @ W1: millions of multiply-and-add steps that don't depend on each other. A GPU (graphics card) was built to colour millions of pixels at once, so it can do thousands of these multiplications at the same time. That's why big models train on GPUs, and why PyTorch has one line to move a model there: model.to("cuda"). Free online notebooks such as Google Colab let you try a GPU without owning one.

⚠️ Common mistakes

  • Only looking at the training score. Always compare it with validation or test: the gap is what matters.
  • Choosing settings with the test set. Then the test score is no longer honest. Use a validation set.
  • Thinking "bigger network = better". Without enough data, a bigger network mostly memorises more.
  • Regularising too hard (huge alpha, tiny max_depth): now the model underfits.
  • Calling .predict before .fit → NotFittedError.

✅ Recap

  • Underfitting: bad on training and new data. Overfitting: great on training, worse on new data (a big gap).
  • Three sets: train to learn, validation to choose, test once at the end.
  • A learning curve shows that more data closes the gap.
  • Regularisation holds a model back: max_depth (trees), alpha (weight penalty), early_stopping=True, dropout.
  • PyTorch and Keras use the same pieces you built: layers, activation, loss, backprop, optimiser, epochs.
